## Возможности

- **E2EE-сообщения** — AES-GCM-256 на каждое сообщение, обмен ключами по ECDH, ключи хранятся в зашифрованном vault в браузере
- **Голосовые и видеозвонки** — WebRTC с TURN-релеем, DTLS-SRTP, мониторинг качества соединения
- **Обмен файлами** — зашифрованная загрузка медиа в MinIO/S3, расшифровка на стороне клиента
- **Группы** — зашифрованное распределение группового ключа по участникам
- **Мультиустройство** — привязка устройств по QR-коду, отзыв доступа
- **2FA** — опциональный TOTP (RFC 6238)
- **PWA** — установка на телефон, push-уведомления через Web Push (VAPID)
- **Самохостинг** — одна команда `./startup.sh`, автоматический TLS через Let's Encrypt

## Быстрый запуск (5 минут)

### 1. Клонирование репозитория

```bash
git clone https://github.com/therudywolf/OneToThree.git
cd OneToThree
```

### 2. Настройка DNS

Создайте пять A-записей, указывающих на IP вашего сервера:

| Запись | Тип | Значение | Прокси Cloudflare |
|--------|-----|----------|-------------------|
| `example.com` | A | `IP_СЕРВЕРА` | Оранжевое облако (проксирование) — можно |
| `api.example.com` | A | `IP_СЕРВЕРА` | Оранжевое облако (проксирование) — можно |
| `s3.example.com` | A | `IP_СЕРВЕРА` | Оранжевое облако (проксирование) — можно |
| `turn.example.com` | A | `IP_СЕРВЕРА` | **Серое облако (только DNS) — ОБЯЗАТЕЛЬНО** |
| `lk.example.com` | A | `IP_СЕРВЕРА` | **Серое облако (только DNS) — ОБЯЗАТЕЛЬНО** |

> **Важно:** Записи `turn.*` и `lk.*` **не должны** быть проксированы. Cloudflare блокирует UDP — TURN-релей и медиапоток LiveKit не работают через прокси. Остальные записи можно проксировать.

### 3. Открытие портов в файрволе

```bash
# Web (Caddy — HTTP challenge + HTTPS)
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp

# TURN / STUN (coturn — обход NAT для WebRTC)
sudo ufw allow 3478/tcp
sudo ufw allow 3478/udp
sudo ufw allow 5349/tcp
sudo ufw allow 49152:65535/udp

# LiveKit SFU — медиапоток и ICE/TCP-фолбек (при использовании SFU для звонков)
sudo ufw allow 7881/tcp
sudo ufw allow 50000:50100/udp
```

### 4. Запуск

```bash
chmod +x ./startup.sh
./startup.sh
```

При **первом запуске** скрипт автоматически:
1. Генерирует все секреты — пароль БД, MinIO, JWT, TURN, VAPID, LiveKit
2. Запрашивает домен, email для ACME, IP сервера и контактный email для VAPID
3. Показывает все учётные данные **один раз** — сохраните их немедленно!
4. Записывает секреты в `./secrets/` (chmod 700, никогда не коммитятся в git)
5. Создаёт `.env.prod` со всеми необходимыми значениями
6. Собирает и запускает все 7 контейнеров
7. Ожидает прохождения health-проверок

TLS-сертификаты получаются автоматически от Let's Encrypt. Первый запуск занимает 2–5 минут.

### 5. Сохраните учётные данные

Учётные данные показываются **только один раз** при первом запуске. Скопируйте их в надёжный менеджер паролей немедленно. Если вы их потеряете, удалите `./secrets/` и перезапустите `./startup.sh` для повторной генерации (существующие данные станут недоступны при новом пароле БД).

### 6. Регистрация и назначение администратора

1. Откройте `https://ваш-домен.ru` в браузере
2. Зарегистрируйте новый аккаунт
3. Назначьте себя администратором:

```bash
docker exec -it forestmessenger-db-1 psql -U forest -d forest \
  -c "UPDATE users SET role = 'admin' WHERE username = 'ваш_никнейм';"
```

4. Откройте `/admin` в браузере (нужно быть авторизованным)

## Что происходит при первом запуске

Когда вы запускаете `./startup.sh` впервые, происходит следующее:

1. **Проверка зависимостей** — убеждается, что Docker, Docker Compose, openssl и curl установлены
2. **Проверка томов** — сообщает, найдены ли существующие тома с данными (при первом запуске их не будет)
3. **Генерация секретов**:
   - Автоматически генерирует: `POSTGRES_PASSWORD`, `MINIO_ROOT_PASSWORD`, `JWT_SECRET`, `WEBHOOK_SECRET`, `TURN_PASSWORD`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`
   - Запрашивает: домен, email для ACME, внешний IP для TURN, контактный email для VAPID
   - Генерирует пару VAPID-ключей (через Docker — потребуется загрузка `node:20-alpine`)
   - Записывает все секреты в `./secrets/` как отдельные файлы (формат Docker secrets)
   - Показывает учётные данные в рамке — **сохраните их сейчас**
4. **Создание env-файла** — записывает `.env.prod` со всеми необходимыми значениями
5. **Валидация** — проверяет, что все обязательные поля заполнены
6. **Проверка TURN** — предупреждает, если TURN и API используют одно имя хоста (конфликт Cloudflare)
7. **Сборка и запуск** — выполняет `docker compose up -d --build`
8. **Health-проверки** — ожидает готовности PostgreSQL, MinIO, API и Next.js
9. **Статус** — выводит состояние контейнеров, URL сайта и полезные команды

> Подробное руководство для начинающих, включая настройку VPS и установку Docker, см. в [docs/guides/FIRST_START.ru.md](./docs/guides/FIRST_START.ru.md).

## Обновление

```bash
./startup.sh update
./startup.sh update --full          # полный rebuild
./startup.sh update --no-cache      # пересборка затронутых образов без cache
./startup.sh update --skip-smoke    # пропустить HTTP smoke checks
```

Эта команда:
1. Загружает последний код из git (`git pull origin main`)
2. Пересобирает Docker-образы
3. Перезапускает контейнеры с `--remove-orphans`
4. Миграции базы данных выполняются автоматически через контейнер `db-migrate` при старте

**Ваши данные в безопасности.** Базы данных, медиафайлы и TLS-сертификаты хранятся в именованных Docker-томах (`pgdata`, `minio_data`, `caddy_data`) и не затрагиваются при пересборке образов.

> **Предупреждение:** Никогда не запускайте `docker compose down -v` — флаг `-v` удаляет все тома и данные.

Подробные инструкции по обновлению, откату и предварительным проверкам см. в [docs/guides/UPDATE.ru.md](./docs/guides/UPDATE.ru.md).

## Резервное копирование и восстановление

### Создание резервной копии

```bash
./startup.sh backup
```

Создаёт сжатый дамп PostgreSQL в файле `backups/db_YYYYMMDD_HHMMSS.sql.gz`.

### Восстановление из резервной копии

```bash
gunzip -c backups/db_20260101_120000.sql.gz | \
  docker compose -f docker-compose.prod.yml --env-file .env.prod \
  exec -T db psql -U forest -d forest
```

> **Примечание:** Медиафайлы хранятся в отдельном томе MinIO. Полная стратегия резервного копирования должна включать и том MinIO:
> ```bash
> docker run --rm -v forestmessenger_minio_data:/data -v $(pwd)/backups:/backup \
>   alpine tar czf /backup/minio_YYYYMMDD.tar.gz -C /data .
> ```

## Android-приложение

Нативное Android-приложение доступно в виде APK (собрано с Capacitor).

### Установить готовый APK

Готовые debug-APK находятся в [`releases/android/`](./releases/android/).

1. Включите «Установку из неизвестных источников» на устройстве.
2. Перенесите и установите `.apk`.
3. При первом запуске укажите адрес вашего сервера.

### Собрать из исходников

Требование: Docker. Локальные Java/Android SDK опциональны; если `ANDROID_HOME` не задан, сборка идёт в Docker Android builder image.

```bash
./startup.sh build-apk                       # debug APK  (берёт URL сервера из .env.prod)
./startup.sh build-apk-release <keystore>    # подписанный release APK
```

На Windows используйте быструю обёртку:

```powershell
.\apkbuild.ps1
.\apkbuild.ps1 -Release -KeystorePath C:\keys\onetothree.jks
```

APK сохраняется в `releases/android/`: стабильное имя плюс timestamped-артефакт для GitHub Release, рядом создаётся `.sha256`.

## Устранение неполадок

| Симптом | Решение |
|---------|---------|
| Caddy не получает TLS-сертификат | Убедитесь, что DNS A-записи указывают на этот сервер. Проверьте, что порты 80 и 443 открыты. Смотрите логи: `./startup.sh logs`, ищите ошибки Caddy. |
| WebRTC-звонки не подключаются | Убедитесь, что DNS `turn.*` установлен в **«Только DNS»** (серое облако) в Cloudflare. Проверьте, что `TURN_EXTERNAL_IP` совпадает с публичным IP сервера (`curl -s ifconfig.me`). Убедитесь, что порты 3478 и 49152–65535/udp открыты. |
| Цикл редиректа на `/login` | Проверьте, что `COOKIE_DOMAIN` установлен как `.ваш-домен.ru` (с точкой в начале) в `.env.prod`. Пересоберите контейнер API после изменений. |
| `relation "users" does not exist` | Ошибка миграции БД. Проверьте: `docker compose -f docker-compose.prod.yml logs db-migrate` |
| Медиа показывает «Файл истёк» | Объект был удалён политикой хранения, либо отправителю нужно переотправить файл. |
| Неверные IP клиентов в логах | Установите `TRUST_PROXY=1` в `.env.prod`, чтобы Fastify читал заголовок `X-Forwarded-For` от Caddy. |
| Контейнеры постоянно перезапускаются | Проверьте лимиты ресурсов. Стеку нужно минимум 4 ГБ RAM. Запустите `./startup.sh logs` для поиска падающего сервиса. |
| `./startup.sh` говорит, что секреты не инициализированы | Удалите `./secrets/` и перезапустите `./startup.sh` для повторной генерации. |

## Архитектура

Стек состоит из 7 Docker-контейнеров:

```
                    ┌─────────┐
                    │  Caddy   │ :80, :443
                    │(обратный │ автоматический TLS
                    │  прокси) │
                    └────┬─────┘
           ┌─────────────┼─────────────┐
           │             │             │
      ┌────▼───┐   ┌────▼───┐   ┌────▼───┐
      │ Next.js│   │ Fastify│   │  MinIO  │
      │  :3000 │   │  :8080 │   │  :9000  │
      └────────┘   └───┬────┘   └─────────┘
                       │
                  ┌────▼────┐
                  │Postgres │
                  │  :5432  │
                  └─────────┘

      ┌──────────┐
      │  coturn   │ :3478 (host-сеть)
      │ TURN/STUN │ :49152–65535/udp
      └──────────┘
```

- **Caddy** — обратный прокси, автоматические HTTPS-сертификаты от Let's Encrypt
- **Next.js** — фронтенд PWA (SSR, статика, сервис-воркер)
- **Fastify** — API-сервер, WebSocket-релей, отправка push-уведомлений
- **PostgreSQL** — аккаунты, метаданные чатов, зашифрованные сообщения
- **MinIO** — S3-совместимое хранилище для зашифрованных медиафайлов
- **db-migrate** — одноразовый контейнер, выполняющий миграции Drizzle ORM при старте
- **coturn** — TURN/STUN-сервер для обхода NAT в WebRTC (host-сеть для UDP)

Подробная архитектура описана в [docs/project/ARCHITECTURE.md](./docs/project/ARCHITECTURE.md).

## Безопасность

OneToThree использует **модель нулевого доверия к серверу**:

- **Приватные ключи никогда не покидают браузер.** Хранилище ключей шифруется локально через Argon2id (t=3, m=64 MiB) + AES-GCM-256; legacy-хранилища автоматически обновляются при разблокировке.
- **Сервер хранит только шифротекст.** Сообщения, медиа и групповые ключи — непрозрачные зашифрованные блобы.
- **Аутентификация через ECDSA challenge-response.** Пароль на сервер никогда не передаётся.
- **Медиа шифруется до загрузки** в MinIO уникальным ключом на каждый файл.
- **WebRTC-сигнализация передаётся как непрозрачные данные** — сервер не разбирает SDP.
- **Инфраструктурные секреты через Docker secrets** — учётные данные монтируются в `/run/secrets/*`, а не хранятся в открытом виде в переменных окружения.

Полная модель угроз, криптографические детали и результаты аудита безопасности описаны в [SECURITY.md](./SECURITY.md).
