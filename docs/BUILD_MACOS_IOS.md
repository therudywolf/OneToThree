# Building OneToThree for macOS & iOS

Everything you need to build the **macOS desktop app** (Tauri `.dmg`) and the
**iOS app** (Capacitor `.ipa`). Both targets can only be built **on a Mac** —
Apple's toolchain (Xcode / `codesign` / CocoaPods) does not run on Windows or
Linux. This repo is otherwise platform-agnostic: the same Next.js static export
(`client/out/`) drives Web, Android, Windows/Linux/macOS desktop, and iOS.

> Windows `.exe`/`.msi` and the Android `.apk` are built on Windows/Linux — see
> [`desktop/tauri/README.md`](../desktop/tauri/README.md) and
> [`RELEASE.md`](RELEASE.md). This document is the macOS/iOS half.

---

## 0. One-time Mac prerequisites

```bash
# 1. Xcode (full IDE, NOT just the CLT) — install from the App Store, then:
sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer
sudo xcodebuild -license accept

# 2. Homebrew (if not present): https://brew.sh
# 3. Node 20+ and Rust
brew install node
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y

# 4. CocoaPods (iOS only)
brew install cocoapods        # or: sudo gem install cocoapods

# 5. Repo deps
git clone https://github.com/therudywolf/OneToThree.git
cd OneToThree
npm ci --no-audit --no-fund
npm install --prefix desktop/tauri
npm install --prefix mobile/capacitor
```

You also need a **`.env.prod`** at the repo root (gitignored). The build reads
the runtime config from it. Minimum:

```dotenv
NEXT_PUBLIC_API_URL=https://api.onetothree.ru
NEXT_PUBLIC_APP_URL=https://onetothree.ru
# Optional — needed only for web-push (VAPID) and TURN-relayed calls:
NEXT_PUBLIC_VAPID_PUBLIC_KEY=
NEXT_PUBLIC_TURN_URLS=
NEXT_PUBLIC_TURN_USERNAME=
NEXT_PUBLIC_TURN_PASSWORD=
```

## A. macOS desktop app (Tauri `.dmg`)

The macOS shell is **already fully configured** — `tauri.conf.json` lists `dmg`
as a bundle target and ships an `.icns` icon. Building is the same flow CI uses
(`.github/workflows/release.yml`, the `macos-14` matrix leg).

```bash
# from repo root
npm run build:client:export                 # builds client/out
cd desktop/tauri
npx @tauri-apps/cli build --bundles dmg
# → src-tauri/target/release/bundle/dmg/OneToThree_0.10.0_aarch64.dmg
#   (x86_64 on Intel Macs; aarch64 on Apple Silicon)
```

Or in one shot: `npm run build:bundles --prefix desktop/tauri` (builds every
target your OS supports).

### Universal (Intel + Apple Silicon) binary — optional

```bash
rustup target add x86_64-apple-darwin aarch64-apple-darwin
npx @tauri-apps/cli build --bundles dmg --target universal-apple-darwin
```

### Known warning — bundle identifier ends in `.app`

The build prints:

> `Warn The bundle identifier "ru.onetothree.app" ... ends with ".app". This is
> not recommended because it conflicts with the application bundle extension on
> macOS.`

This is **non-fatal** — the `.dmg` still builds. The identifier is shared with
Android (`applicationId`), the OS-keychain service namespace, and the deep-link
config, so we keep it as-is for the alpha. If a future macOS toolchain promotes
this to an error, override it **for the macOS build only** without touching the
committed config:

```bash
npx @tauri-apps/cli build --bundles dmg --config '{"identifier":"ru.onetothree.desktop"}'
```

### Signing & notarization (required for distribution, optional for local use)

Alpha `.dmg`s are **unsigned** → Gatekeeper warns on first launch (right-click ▸
Open to bypass). For public distribution you need an Apple Developer ID:

```bash
# Sign during build (Tauri picks these up):
export APPLE_SIGNING_IDENTITY="Developer ID Application: Your Name (TEAMID)"
export APPLE_ID="you@example.com"
export APPLE_PASSWORD="app-specific-password"   # appleid.apple.com ▸ App-Specific Passwords
export APPLE_TEAM_ID="TEAMID"
npx @tauri-apps/cli build --bundles dmg
# Tauri will codesign and submit to Apple's notary service automatically when
# these env vars are present.
```

## B. iOS app (Capacitor `.ipa`)

iOS is **not yet scaffolded** in the repo (there is no `mobile/capacitor/ios/`).
The first build creates it. `@capacitor/ios` is already wired into
`mobile/capacitor/package.json`, and the npm scripts + a build script are in
place.

### B.1 First-time scaffold

```bash
# from repo root — creates mobile/capacitor/ios/ and runs pod install
npm run build:client:export
npm run ios:add            # == cap add ios   (commit the generated ios/ folder)
```

`cap add ios` generates the Xcode project from the Capacitor template. Commit
`mobile/capacitor/ios/` (the `Pods/` folder is gitignored and regenerated by
`pod install`).

### B.2 App icons & splash (from the wolf logo)

```bash
# @capacitor/assets is a devDependency of mobile/capacitor
mkdir -p mobile/capacitor/assets
cp client/public/wolf-logo.png mobile/capacitor/assets/icon.png   # 1024×1024 source
cp client/public/wolf-logo.png mobile/capacitor/assets/splash.png
cd mobile/capacitor
npx @capacitor/assets generate --ios   # writes the iOS AppIcon + splash sets
```

### B.3 Build

A helper script mirrors `scripts/build-apk.sh`:

```bash
# web build + cap sync, then open Xcode to archive manually:
./scripts/build-ipa.sh

# build for the iOS Simulator (no Apple account / signing needed):
./scripts/build-ipa.sh simulator

# fully automated signed archive + .ipa export (needs an Apple Developer team):
IOS_DEVELOPMENT_TEAM=A1B2C3D4E5 IOS_EXPORT_METHOD=development \
  ./scripts/build-ipa.sh archive
# → releases/ios/ipa/App.ipa
```

`IOS_EXPORT_METHOD` is one of `development`, `ad-hoc`, `app-store`,
`enterprise`. For TestFlight / App Store, use `app-store` and an
App Store Connect API key or an Xcode-managed account.

### B.4 Required native config (do once, in Xcode, after `cap add ios`)

The Android shell has features that need matching iOS configuration. After
scaffolding, edit `mobile/capacitor/ios/App/App/Info.plist` and the target's
Signing & Capabilities tab:

| Capability | Android equivalent | iOS setup |
|---|---|---|
| **Custom URL scheme** `onetothree://` | `<data android:scheme="onetothree">` | `Info.plist` → `CFBundleURLTypes` → URL scheme `onetothree` |
| **Universal Links** `https://onetothree.ru/join/*` | App Links + `assetlinks.json` | Signing&Capabilities ▸ **Associated Domains** → `applinks:onetothree.ru`; publish AASA (below) |
| **Push notifications** | FCM / foreground service | Capabilities ▸ **Push Notifications** + **Background Modes ▸ Remote notifications**; APNs key in Apple Developer portal |
| **Camera** | `CAMERA` | `NSCameraUsageDescription` |
| **Microphone (calls)** | `RECORD_AUDIO` | `NSMicrophoneUsageDescription` |
| **Photo library** | `READ_MEDIA_IMAGES/VIDEO` | `NSPhotoLibraryUsageDescription`, `NSPhotoLibraryAddUsageDescription` |
| **Screenshot/recording block** | `FLAG_SECURE` (on by default) | No system flag — implement a secure-overlay on `sceneWillResignActive` (see `client/src/lib/native-flag-secure.ts`; tracked as a follow-up) |

Copy-paste `Info.plist` keys:

```xml
<key>CFBundleURLTypes</key>
<array><dict>
  <key>CFBundleURLName</key><string>ru.onetothree.app</string>
  <key>CFBundleURLSchemes</key><array><string>onetothree</string></array>
</dict></array>
<key>NSCameraUsageDescription</key><string>OneToThree uses the camera for video calls and sending photos.</string>
<key>NSMicrophoneUsageDescription</key><string>OneToThree uses the microphone for voice and video calls.</string>
<key>NSPhotoLibraryUsageDescription</key><string>OneToThree accesses your photo library to share images.</string>
```

The JS deep-link handler is already cross-platform (it listens to the Capacitor
`App` plugin's `appUrlOpen` event — see
`client/src/components/native-deep-link.tsx`), so no web-side changes are
needed.

### B.5 Universal Links server file (AASA)

Universal Links require Apple to fetch
`https://onetothree.ru/.well-known/apple-app-site-association` (served as
`application/json`, **no** `.json` extension, over HTTPS, no redirect). A
template is committed at
[`client/public/.well-known/apple-app-site-association`](../client/public/.well-known/apple-app-site-association)
— replace `TEAMID` with your Apple Team ID before deploying:

```json
{ "applinks": { "details": [
  { "appIDs": ["TEAMID.ru.onetothree.app"], "components": [{ "/": "/join/*" }] }
]}}
```

This is the iOS counterpart of Android's
[`assetlinks.json`](../client/public/.well-known/assetlinks.json) (already filled
in with the release keystore's SHA-256).

## C. Shared notes

- **VAPID / TURN secrets** are baked into the static export at build time. They
  live on the production server's `.env.prod`. Without them: web-push is off
  (the apps fall back to in-app/native notification paths) and calls can't use a
  TURN relay (direct/STUN still works). Copy the real values into your local
  `.env.prod` for a production-parity build.
- **Version bumping** before a release (see `RELEASE.md`): `VERSION` is the single
  source of truth. Bump `VERSION` + the desktop mirror files
  (`desktop/tauri/package.json`, `desktop/tauri/src-tauri/Cargo.toml`,
  `desktop/tauri/src-tauri/tauri.conf.json`) + the README badges + CHANGELOG.
  `client/package.json`, `server/package.json` and `mobile/capacitor/package.json`
  are **intentionally decoupled** (stay `0.1.0`, never read for a user-facing
  version — the client bakes `VERSION` via `next.config.js`, the server reads
  `VERSION`, and the Android build derives versionName/Code from `VERSION`).
  `Cargo.lock`'s `onetothree-tauri` version regenerates from `Cargo.toml` on the
  next `cargo`/`tauri build`.
  Note: the MSI bundler rejects non-numeric pre-release tags; releases now use clean
  numeric semver (e.g. `0.10.0`), so no override is needed. If a pre-release tag is
  ever used again, build MSI with a numeric `--config '{"version":"X.Y.Z"}'`
  override while `.dmg`/NSIS/APK keep the full semver.
- **CI** (`.github/workflows/release.yml`) already has a `macos-14` leg that
  builds the `.dmg` on tag push, but **GitHub Actions billing is disabled**
  (owner decision), so all releases are currently built locally. There is **no
  iOS CI job** yet — add one (macOS runner + the steps above) when ready.
