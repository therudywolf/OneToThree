## 1. Подготовка сервера

Вам нужен Linux VPS со следующими характеристиками:

| Ресурс | Минимум | Рекомендуется |
|--------|---------|---------------|
| CPU | 2 vCPU | 4 vCPU |
| RAM | 4 ГБ | 8 ГБ |
| Диск | 20 ГБ SSD | 40+ ГБ SSD |
| ОС | Ubuntu 22.04 LTS | Ubuntu 22.04/24.04 LTS |

Подключитесь к серверу по SSH:

```bash
ssh root@IP_ВАШЕГО_СЕРВЕРА
```

Обновите систему:

```bash
apt update && apt upgrade -y
```

## 2. Установка Docker

Если Docker ещё не установлен, выполните следующие команды:

```bash
# Установка зависимостей
apt install -y ca-certificates curl gnupg

# Добавление GPG-ключа Docker
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | gpg --dearmor -o /etc/apt/keyrings/docker.gpg
chmod a+r /etc/apt/keyrings/docker.gpg

# Добавление репозитория Docker
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  tee /etc/apt/sources.list.d/docker.list > /dev/null

# Установка Docker Engine и плагина Compose
apt update
apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

Проверьте установку:

```bash
docker --version
# Docker version 27.x.x ...

docker compose version
# Docker Compose version v2.x.x ...
```

## 3. Настройка DNS

Вам нужен домен (например, `messenger.example.com`) с четырьмя A-записями. Перейдите в панель управления DNS (или Cloudflare) и создайте записи:

```
example.com         →  A  →  IP_ВАШЕГО_СЕРВЕРА
api.example.com     →  A  →  IP_ВАШЕГО_СЕРВЕРА
s3.example.com      →  A  →  IP_ВАШЕГО_СЕРВЕРА
turn.example.com    →  A  →  IP_ВАШЕГО_СЕРВЕРА
```

**Распространение DNS** может занять до 24 часов, но обычно завершается за несколько минут. Проверьте командой:

```bash
dig +short example.com
dig +short api.example.com
dig +short s3.example.com
dig +short turn.example.com
```

Все четыре записи должны возвращать IP-адрес вашего сервера.

## 4. Настройка Cloudflare (если используется)

Если вы используете Cloudflare для управления DNS, настройте режим прокси для каждой записи:

| Запись | Режим прокси |
|--------|-------------|
| `example.com` | Проксирование (оранжевое облако) |
| `api.example.com` | Проксирование (оранжевое облако) |
| `s3.example.com` | Проксирование (оранжевое облако) |
| `turn.example.com` | **Только DNS (серое облако)** |

> **Почему серое облако для `turn.*`?** Прокси Cloudflare не поддерживает UDP-трафик. TURN-серверу необходим прямой доступ по UDP для ретрансляции WebRTC-вызовов. Если `turn.*` проксируется, голосовые и видеозвонки перестанут работать.

Как изменить режим прокси в Cloudflare:
1. Перейдите в настройки DNS вашего домена
2. Найдите запись `turn.*`
3. Нажмите на оранжевое облако — оно должно стать серым
4. Сохраните

Также убедитесь, что режим SSL/TLS в Cloudflare установлен на **Full (strict)**, если вы проксируете остальные записи. Caddy получает собственные сертификаты, и Cloudflare должен им доверять.

## 5. Открытие портов в файрволе

```bash
# Веб-трафик (обратный прокси Caddy)
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp

# TURN-сервер (coturn)
sudo ufw allow 3478/tcp
sudo ufw allow 3478/udp
sudo ufw allow 5349/tcp

# Порты ретрансляции TURN (медиа WebRTC)
sudo ufw allow 49152:65535/udp

# Включить файрвол, если ещё не активен
sudo ufw enable
```

Проверьте:

```bash
sudo ufw status
```

Все перечисленные выше порты должны быть в списке как ALLOW.

## 7. Запуск startup.sh

```bash
chmod +x ./startup.sh
./startup.sh
```

### Что означает каждый запрос

Скрипт задаст четыре вопроса:

1. **Enter your domain (e.g. onetothree.ru):**
   Введите только доменное имя без `https://`. Пример: `messenger.example.com`

2. **Enter ACME email for TLS certs:**
   Ваш email для уведомлений о сертификатах Let's Encrypt. Пример: `admin@example.com`

3. **Enter TURN server external IP:**
   Публичный IP-адрес вашего сервера. Узнайте его командой: `curl -s ifconfig.me`

4. **Enter VAPID contact email:**
   Контактный email для push-уведомлений. Может совпадать с email для ACME. Пример: `admin@example.com`

### Что происходит дальше

После ответов на вопросы скрипт:
1. Генерирует все секреты и выводит их в рамке — **скопируйте их сейчас**
2. Создаёт `.env.prod` и автоматически заполняет все значения
3. Загружает Docker-образы и собирает приложение (это занимает несколько минут)
4. Ожидает прохождения health-проверок каждого сервиса
5. Выводит финальный статус с URL вашего сайта

Вы увидите вывод вроде этого:

```
  PostgreSQL     ✓ healthy
  MinIO          ✓ healthy
  API            ✓ healthy
  Next.js        ✓ healthy

  ✓ OneToThree запущен

  Сайт:    https://messenger.example.com
  API:     https://api.messenger.example.com
  Сервер:  IP_ВАШЕГО_СЕРВЕРА
```

## 8. Сохранение учётных данных

Во время первого запуска вы увидите рамку:

```
╔══════════════════════════════════════════════════════════╗
║              SAVE THESE CREDENTIALS — SHOWN ONCE        ║
╠══════════════════════════════════════════════════════════╣
║ POSTGRES_PASSWORD  : ...
║ MINIO_PASSWORD     : ...
║ JWT_SECRET         : ...
║ WEBHOOK_SECRET     : ...
║ TURN_PASSWORD      : ...
║ VAPID_PUBLIC_KEY   : ...
║ VAPID_PRIVATE_KEY  : ...
╚══════════════════════════════════════════════════════════╝
```

**Скопируйте всё в надёжный менеджер паролей немедленно.** Эти данные показываются только один раз и не могут быть восстановлены позже.

Если вы их потеряли:
1. Остановите стек: `./startup.sh stop`
2. Удалите секреты: `rm -rf ./secrets/`
3. Перезапустите: `./startup.sh`
4. Это сгенерирует новые секреты, но **существующие данные в БД станут недоступны** с новым паролем

## 9. Проверка работоспособности

Пройдите по этому чеклисту:

- [ ] `./startup.sh status` — все контейнеры показывают "healthy" или "Up"
- [ ] Откройте `https://ваш-домен.ru` в браузере — загружается страница регистрации
- [ ] Проверьте TLS-сертификат — значок замка показывает валидный сертификат Let's Encrypt
- [ ] Зарегистрируйте новый аккаунт — процесс регистрации завершается успешно
- [ ] Отправьте тестовое сообщение себе (создайте заметку/чат)
- [ ] Проверьте `https://api.ваш-домен.ru/health` — возвращает ответ
- [ ] Протестируйте голосовой звонок между двумя устройствами (нужны два аккаунта)

Если что-то не работает, смотрите раздел [Устранение неполадок](../../README.ru.md#устранение-неполадок) в README.

## 10. Назначение администратора

После регистрации аккаунта назначьте его владельцем (высшая группа `creator`).
Проще всего — указать ник в окружении api и перезапустить api:

```bash
# .env.prod
ADMIN_BOOTSTRAP_USERNAME=ваш_никнейм
```

Повышение происходит на старте и только пока на сервере нет ни одного
создателя — дальше переменная ничего не делает, её можно оставить. Аккаунт она
не создаёт: сначала зарегистрируйтесь.

Либо руками. Источник истины — `user_group`, а `role` из неё производится,
поэтому ставим оба:

```bash
docker exec -it forestmessenger-db-1 psql -U forest -d forest \
  -c "UPDATE users SET user_group = 'creator', role = 'admin' WHERE username = 'ваш_никнейм';"
```

Замените `ваш_никнейм` на точное имя пользователя, с которым вы зарегистрировались.
(`creator` — неизменяемая группа владельца: может назначать/снимать админов, обычный
`admin` — нет.)

Затем откройте `https://ваш-домен.ru/admin` в браузере (нужно быть авторизованным). Вы должны увидеть панель администратора.

## 11. Установка PWA на телефон

OneToThree — это Progressive Web App (PWA), его можно установить на телефон как обычное приложение:

### Android (Chrome)
1. Откройте `https://ваш-домен.ru` в Chrome
2. Нажмите на три точки (вверху справа)
3. Нажмите «Установить приложение» или «Добавить на главный экран»
4. Подтвердите установку

### iOS (Safari)
1. Откройте `https://ваш-домен.ru` в Safari
2. Нажмите кнопку «Поделиться» (внизу по центру)
3. Прокрутите вниз и нажмите «На экран "Домой"»
4. Нажмите «Добавить»

### Десктоп (Chrome/Edge)
1. Откройте `https://ваш-домен.ru`
2. Нажмите на значок установки в адресной строке (или три точки → «Установить OneToThree»)

После установки приложение:
- Открывается в собственном окне (без интерфейса браузера)
- Получает push-уведомления
- Работает оффлайн (показывает баннер при потере соединения)
