## Когда обновляться

Следите за новыми релизами и изменениями:

- **Релизы на GitHub:** https://github.com/therudywolf/OneToThree/releases
- **История коммитов:** `git log --oneline origin/master..HEAD` (показывает, что нового в upstream)

Обновляйтесь при выходе исправлений безопасности, багфиксов или новых функций, которые вам нужны.

---

## Перед обновлением: создайте резервную копию

Всегда создавайте резервную копию перед обновлением:

```bash
./startup.sh backup
```

Создаёт сжатый дамп базы данных в `backups/db_YYYYMMDD_HHMMSS.sql.gz`.

Для полного резервного копирования, включая медиафайлы:

```bash
# База данных
./startup.sh backup

# Медиа (том MinIO)
docker run --rm -v forestmessenger_minio_data:/data -v $(pwd)/backups:/backup \
  alpine tar czf /backup/minio_$(date +%Y%m%d_%H%M%S).tar.gz -C /data .
```

## Команда обновления

```bash
./startup.sh update
```

Одна команда — и всё.

---

## Что происходит внутри

Команда `./startup.sh update` выполняет следующие шаги:

1. **`git pull origin master`** — загружает последний исходный код
2. **`docker compose up -d --build --remove-orphans`** — пересобирает Docker-образы из обновлённого кода и перезапускает контейнеры; удаляет контейнеры от удалённых сервисов
3. **Миграции базы данных** — контейнер `db-migrate` запускается автоматически при каждом старте, применяя новые миграции Drizzle ORM к схеме базы данных

Весь процесс обычно занимает 3–5 минут, в зависимости от объёма изменений и скорости сборки на сервере.

## Проверка обновления

После завершения обновления:

```bash
# Проверить, что все контейнеры здоровы
./startup.sh status

# Проверить логи на наличие ошибок
./startup.sh logs

# Убедиться, что сайт загружается
curl -sI https://ваш-домен.ru | head -5
```

Если `db-migrate` показывает ошибки, проверьте его логи отдельно:

```bash
docker compose -f docker-compose.prod.yml logs db-migrate
```

## Откат при проблемах

Если обновление вызвало проблемы, можно откатиться на предыдущую версию:

### 1. Найдите предыдущий коммит

```bash
git log --oneline -10
```

### 2. Переключитесь на предыдущий коммит

```bash
git checkout ХЕШ_ПРЕДЫДУЩЕГО_КОММИТА
```

### 3. Пересоберите и перезапустите

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build --remove-orphans
```

### 4. Восстановите базу данных (при необходимости)

Если миграция внесла деструктивные изменения и нужно восстановить данные:

```bash
gunzip -c backups/db_YYYYMMDD_HHMMSS.sql.gz | \
  docker compose -f docker-compose.prod.yml --env-file .env.prod \
  exec -T db psql -U forest -d forest
```

### 5. Вернитесь к отслеживанию master

Когда проблема решена в upstream:

```bash
git checkout master
git pull origin master
./startup.sh update
```

## Почему данные в безопасности

Все постоянные данные хранятся в именованных Docker-томах:

| Том | Содержимое |
|-----|-----------|
| `forestmessenger_pgdata` | База данных PostgreSQL (пользователи, сообщения, метаданные чатов) |
| `forestmessenger_minio_data` | Зашифрованные медиафайлы |
| `forestmessenger_caddy_data` | TLS-сертификаты (Let's Encrypt) |
| `forestmessenger_caddy_config` | Состояние конфигурации Caddy |

Эти тома **никогда не затрагиваются** командой `docker compose up --build`. Пересборка образов заменяет только код контейнеров, но не тома.

> **Предупреждение:** Единственная команда, удаляющая тома — `docker compose down -v`. Никогда не используйте флаг `-v`, если вы не хотите намеренно стереть все данные.

### Что НЕ хранится в томах

- Код приложения (пересобирается из исходников при каждом обновлении)
- Модули Node.js (пересобираются внутри контейнеров)
- Временные файлы (очищаются при перезапуске контейнера)

Всё это регенерируется автоматически в процессе сборки.
