### A. Security / InfoSec

| Sev | File:Line | Issue | Fix |
|---|---|---|---|
| **P0** | `client/src/lib/ratchet/session-manager.ts:553-572` `acceptIncomingInit` | Wire-supplied `initiatorIdentityExchange` / `initiatorIdentitySigning` are accepted **without fetching the published bundle** for `peerId` and asserting equality. Anyone authenticated who can reach `POST /messages/send` with `protocol_version=2` and a forged `dr_init` can bootstrap a DR session as a forged identity. Bob's TOFU then pins the attacker's keys. Mitigated today only because DR is gated off by default (`NEXT_PUBLIC_DR_ENABLED`). | Fetch peer bundle via `keysApi.fetchBundle(peerId)`; reject if `b64urlEncode(bundle.identitySigning) !== init.initiatorIdentitySigning` OR `bundle.identityExchange !== init.initiatorIdentityExchange`. Throw `X3DH_IDENTITY_MISMATCH`. Add ratchet test that forges identity. |
| **P0** | `server/src/routes/ws.ts:122,388-432` WS `chat_message` handler | Persists messages via `persistChatMessageAndFanOut` but: (a) does NOT enforce `DIRECT_FANOUT_REQUIRED` (no `ciphertexts[]` validation), (b) skips the `protocol_version=2 ⇒ dr_header` zod refine, (c) skips channel posting permission, (d) does not pin `senderEcdhPublicKeyJwk`. A buggy or malicious client can persist a direct message with shared `content/iv` bypassing E2EE-per-device invariant. | The REST path (`POST /messages/send`) is the only one the current client uses. Either DELETE the WS handler, or mirror REST validation 1:1 (refine, channel role, sender key pin, `DIRECT_FANOUT_REQUIRED`). Recommended: delete. |
| **P1** | `server/src/routes/chats.ts:521` `GET /join/:code` | Mutating endpoint exposed as GET. With `SameSite=None` session cookies in production, a third-party page can trigger silent group join via `<img src=...>`. No CORS preflight on simple GET. | Switch to `POST`, require JSON body, add rate limit `{ max: 10, timeWindow: '1 minute' }`. Update client `use-invite-join` accordingly. |
| **P1** | `server/src/routes/users.ts:688-701` `DELETE /me/devices/:deviceId` (single) | Sibling endpoints (`clear-revoked`, `revoke-all-others`, `master`, `history-sync`) all call `requireTotpStepUp(request, user.id)`; the single-device delete does NOT. A hijacked session can revoke any non-master device without 2FA. | Add `requireTotpStepUp` at the top of the handler. |
| **P1** | `server/src/routes/messages.ts` `POST /messages/:id/pin` | Same handler runs for `direct_e2e`, `group_e2e`, `channel`. In channels, subscribers can pin/unpin. | Branch on `chat.type`: groups → require `role in {owner,admin}`; channels → require `channelRole in {editor,owner}`. |
| **P1** | `client/src/lib/chat-crypto.ts` trust-store check | If localStorage trust registry is missing or fails JSON.parse, the verification is silently skipped — first MITM key becomes the new TOFU pin. | Treat parse error as `SECURITY_REGISTRY_CORRUPT`. On first contact, render a banner requiring user to accept the safety number before chat unlocks. |
| **P1** | `server/src/routes/devices.ts` `POST /link/confirm` | `ip_address` and `user_agent` come from request **body**, not server-derived. Audit log in `/me/devices` shows attacker-controlled metadata. | Use `request.ip` and `request.headers['user-agent']`; drop the body fields. |
| **P2** | `Caddyfile:20` CSP | `script-src 'self' 'unsafe-inline'` + `connect-src 'self' wss: https:` are weak; any in-page script injection can exfiltrate to any HTTPS origin. | Move to nonce-based CSP (Next.js 16 supports). Enumerate `connect-src` (api, s3 subdomain, giphy, livekit, turn). Test both `data-shell` modes. |
| **P2** | `client/src/lib/vault.ts` v4 blob | v4 GCM doesn't bind argon2 params via AAD. v5 fixes this; legacy v4 blobs are accepted on read without forced rewrap. | Verify `upgradeVaultBlob` is called from every successful v4 unwrap path; if not, wire it in. |
| **P2** | `server/src/routes/chats.ts` 17 mutating endpoints | favorite, mute, leave, invite, role-patch, kick, delete — none have `rateLimit` config. Only `POST /` and `/discover` do. | Baseline `{ max: 30, timeWindow: '1 minute' }` on every mutating handler. |
| **P2** | `docker-compose.yml:15-17,53-54` | DB binds `5432:5432` to host, MinIO uses default `minio_secret_change_me`. OK for dev compose but trivially shippable. | Verify `docker-compose.prod.yml` removes host port and rejects default creds. Add `config/env/.env.prod.example` with explicit warning. |
| **P3** | `docker-compose.yml:99-100` | `AUTH_CHALLENGE_RATE_LIMIT_MAX: 100` dev value — verify prod overlay overrides. | Audit prod overlay. |
