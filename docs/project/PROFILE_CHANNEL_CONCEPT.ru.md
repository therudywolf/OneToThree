## 1. Суть

Как в Telegram: свой канал используется как публичная страница/стена, и он
**прилинкован к профилю** — открыв профиль человека, видишь его канал и можешь
подписаться. У нас каналы уже есть как тип чата, профиль уже имеет bio/статус/
соцссылки — не хватает ровно одного ребра «пользователь → его канал» и починки
самих каналов (см. §3: сейчас в канал нельзя написать даже владельцу).

## 2. Что уже есть (карта кода)

**Каналы — это тип чата, не отдельная сущность:**

- `chat_type` enum: `direct_e2e | group_e2e | public_open | channel` —
  `server/src/db/schema.ts:23`.
- Права постинга — вторая роль `channel_role` (`subscriber | editor | owner`)
  на `chat_members` (`schema.ts:39`, инвариант-триггер в
  `server/drizzle/0030_channels_members.sql`). `role` — членство/модерация,
  `channel_role` — право писать.
- Создание: единый `POST /api/chats` (`server/src/routes/chats.ts:819`),
  клиентская модалка `create-group-modal.tsx` с переключателем
  «Группа (E2E) / Канал (Broadcast)».
- Пермалинк канала: `chats.invite_slug` (`schema.ts:241`,
  `PATCH /chats/:id/invite-slug` — `chats.ts:1164`); join принимает и код,
  и slug (`chats.ts:686`).
- Каталог: `GET /chats/discover` (`chats.ts:1821`) + `explore-modal.tsx`
  («Группы и каналы»).
- Сервер честно запрещает постинг подписчикам: `messages.ts:165-167`
  (`CHANNEL_SUBSCRIBERS_CANNOT_POST`), WS-обход закрыт (`ws.ts:667-681`).

**Профиль:**

- `users`: `display_name`, `bio`, `status_text`, `social_links`, `avatar_key`,
  `is_discoverable`, приватность last seen (`server/src/db/schema.ts:73-157`).
- Публичный профиль: `GET /users/:username/profile` (`users.ts:533-606`,
  гейт на `is_discoverable` от перечисления хэндлов) →
  `user-profile-modal.tsx` (bio, статус, соцссылки, общие медиа).
- Настройки профиля: `settings-modal.tsx`, вкладка «Профиль»
  (аватар, имя, bio, статус, приватность, соцссылки).
- «Моя ссылка» = `/?invite=<UUID>`; UUID-ссылка сознательно работает как
  capability даже для скрытых пользователей (`users.ts:854-862`).

**Чего нет совсем:** ни `users.profile_channel_id`, ни `chats.owner_id`, ни
какого-либо понятия «личный канал» / «стена» (проверено поиском по
`client/src`, `server/src`, `server/drizzle`, `docs`).

## 3. Ревизия: каналы сейчас наполовину пришиты

`FEATURE_MATRIX.md:51` числит каналы как `implemented` — по факту это не так.
Пока это не починено, «стена» невозможна: канал, в который нельзя постить, —
не стена.

**P0 — блокирует всё:**

1. **Постить в канал нельзя вообще, даже владельцу.**
   `buildChatCryptoContext` разбирает `public_open | direct_e2e | group_e2e`
   и для `channel` падает в `return null`
   (`client/src/lib/chat-crypto.ts:219-256`) →
   `use-chat-crypto-context.ts:81-84` превращает это в вечный
   `CRYPTO_BACKEND_PENDING` → композер и вложения заблокированы
   (`chat-app.tsx`). Фикс: ветка `chat.type === 'channel'` →
   `{ mode: 'PUBLIC' }` (каналы по дизайну plaintext-broadcast, как
   `public_open`; серверный гейт по `channel_role` уже стоит). Проверить
   отправку/приём/медиа после фикса.
2. **`PATCH /chats/:id/members/:userId/channel-role` не существует на сервере.**
   Клиент зовёт его (`client/src/lib/api/chats.ts:412-430`) — 404. Из-за этого
   в настройках канала не работают ни кнопки «кто может постить», ни
   per-member роль фида (`group-chat-settings.tsx:216`, `:455`).
3. **`GET /chats/:id` не отдаёт `channel_role` участников** (карта ответа —
   `chats.ts:1794-1816`), клиентский тип его ждёт (`api/chats.ts:58`) — в UI
   все выглядят подписчиками. Заодно не отдаётся `discussion_chat_id`.

**P1 — нужно для полноценной «страницы»:**

4. **Метаданных канала нет.** Ни аватара, ни описания, ни переименования:
   в `chats` нет колонок `avatar_key`/`description`, а `PATCH /chats/:id`
   вообще отсутствует (имя write-once при создании). Для «стены» минимум —
   миграция (+2 колонки) и `PATCH /chats/:id {name, description, avatar_key}`
   (owner-only) + UI в `group-chat-settings.tsx`.
5. **`PATCH /chats/:id/discussion` не реализован** — признание прямо в
   `schema.ts:245-250`; пикер обсуждения в настройках канала 404-ит.
   Либо реализовать, либо спрятать UI до реализации.

**P2 — полировка:**

6. В списке чатов канал неотличим от группы — одинаковая плитка и подпись
   «N участников» (`chat-sidebar.tsx:1106-1109`). Нужен Megaphone-бейдж и
   «N подписчиков».
7. Лейбл поля имени в режиме канала — «Название группы»
   (`create-group-modal.tsx:247` → `group.channelName`, `ru.ts:503`).
8. `chat-folders.ts:324-335` сваливает `public_open` в «каналы» — папка
   «Каналы» ловит и публичные группы.

## 4. Концепт «Личный канал»

### 4.1 Данные — одна колонка

```sql
ALTER TABLE users ADD COLUMN profile_channel_id uuid
  REFERENCES chats(id) ON DELETE SET NULL;
```

Указатель на `users`, а не флаг на `chats`: каналов у человека много,
прилинкован один; валидация тривиальна; удаление канала само отвязывает
(`ON DELETE SET NULL`). Новых таблиц нет.

### 4.2 Сервер

- `PATCH /users/me` (`users.ts:60` — `patchMeSchema`): принять
  `profile_channel_id: uuid | null`. При не-null проверять: чат существует,
  `type = 'channel'`, вызывающий — владелец (`chat_members.role = 'owner'`).
  Ошибки: `NOT_CHANNEL_CHAT` / `NOT_CHANNEL_OWNER`.
- `GET /users/:username/profile` (`users.ts:533`): в ответ добавить
  `profile_channel: { id, name, invite_slug, member_count } | null`.
  Отдавать только если у канала есть постоянный `invite_slug` **или**
  многоразовый `invite_code`; одноразовый код не отдавать — паттерн уже есть
  в discover (`chats.ts:1867-1872`). Приватность: сам профиль уже гейтится
  `is_discoverable`, привязка добровольная — отдельного тумблера на старте
  не нужно.

### 4.3 Клиент

- **Настройки → Профиль**: блок «Мой канал» — селект своих каналов
  (список чатов уже есть; фильтр `type === 'channel' && my_role === 'owner'`),
  кнопки «Создать канал» (открывает `create-group-modal` в режиме `channel`)
  и «Отвязать».
- **Публичный профиль** (`user-profile-modal.tsx`, после соцссылок):
  карточка канала — Megaphone, имя, N подписчиков; если уже участник —
  «Открыть» (фокус чата), иначе «Подписаться» →
  `POST /chats/join/<slug|code>` → открыть. Позже то же в `dock-panel.tsx`.

### 4.4 Порядок работ

1. §3 P0 (починка постинга + channel-role роут + поля в detail) —
   без этого дальше идти некуда.
2. §4.1–4.3 (колонка, PATCH-валидация, карточка в профиле, блок в настройках).
3. §3 P1 (метаданные канала — аватар/описание делают «страницу» страницей).
4. §3 P2 + «поделиться каналом» (ссылка на slug) из карточки.

Шаги 1–2 — примерно день работы с тестами; сервер покрывать по образцу
`chats-ops.test.ts` / `users-profile-settings.test.ts`.

## 5. Прочие находки ревизии (профиль)

- **bio: UI разрешает 500, сервер режет 256** (`settings-modal.tsx` maxLength
  500 + счётчик `/500` против `users.ts:67` max 256) → сохранение длинного bio
  падает `INVALID_BODY`. Выровнять (проще UI → 256).
- **Кнопки «Блок» и «Жалоба» в профиле мёртвые** — иконки без `onClick`
  (`user-profile-modal.tsx:273-286`), при живом API блокировки
  (`users.ts:1239`, `:1258`, `:1271`).
- **«Общие группы» — фикция**: клиент рисует секцию (`user-profile-modal.tsx:360-381`),
  сервер поле `mutual_groups` не отдаёт (`users.ts:594-605`) — всегда пусто.
- **`display_name` не доезжает** до списка чатов/шапки: `/auth/me` отдаёт
  только `id, username, role, avatar_key` (`auth.ts:160-166`).
- Ссылка-приглашение — голый UUID. Красивый вариант «поделиться собой» после
  этого концепта — ссылка на **канал** (slug), а не на профиль: slug публичен
  по определению, а UUID-ссылка остаётся capability для лички.

## 6. Сделано (код, 2026-08-12; в рабочем дереве — на прод НЕ выкатывалось)

**Вторая итерация — ремонт каналов + профиль + сама фича:**

- **Постинг в каналы ожил**: ветка `channel → { mode: 'PUBLIC' }` в обоих
  билдерах `chat-crypto.ts` (основной + WithMeta/форвард). Серверный гейт по
  `channel_role` уже стоял.
- **`PATCH /chats/:id/members/:userId/channel-role`** реализован (owner-only,
  только `subscriber|editor` — `owner` двигается только переносом владения;
  лимит 120/мин, т.к. кнопки режима постинга шлют PATCH на каждого участника).
  Из клиентского селекта убрана опция `owner`.
- **`PATCH /chats/:id/discussion`** реализован: owner-only, цель —
  `group_e2e|public_open`, владелец обязан быть её участником, `null` отвязывает.
- **`GET /chats/:id`** теперь отдаёт `channel_role` каждого участника и
  `discussion_chat_id` — настройки канала показывают реальные роли.
- **Привязка канала к профилю (§4) реализована**: миграция
  `0061_users_profile_channel.sql` (+journal) и `users.profileChannelId` в
  схеме; `PATCH /users/me` принимает `profile_channel_id` с проверкой
  «канал + владелец» (`NOT_CHANNEL_CHAT` / `NOT_CHANNEL_OWNER`);
  `/users/me/settings` и публичный профиль отдают его; в профиле — карточка
  канала (имя, N подписчиков, «Подписаться» через join по slug/коду, для
  участника join идемпотентен) — только если у канала есть стабильный
  join-handle (одноразовый код не отдаётся, правило discover); в
  Настройки → Профиль — блок «Мой канал» (селект своих каналов / «Не привязан»).
- **Профиль**: bio-лимит выровнен (UI 256 = сервер); «Блок» работает
  (двухклик-подтверждение, тоггл «Разблокировать», `/users/me/block*`);
  «Жалоба» убрана (API жалоб нет); «Общие группы» реально отдаются сервером
  (пересечение групповых чатов, direct не течёт, лимит 20).
- **Тесты**: `chats-channels.test.ts` (гейт постинга, channel-role, discussion),
  `users-profile-mutual-groups.test.ts`, `users-profile-channel.test.ts`.
  Сервер: 246 тестов / 58 файлов зелёные; клиент: 391 / 67 зелёные; typecheck
  и eslint обоих воркспейсов чистые.
